# Roundtable 产品说明书

> **面向审查官的非技术说明文档**

---

## 一、200 字产品简介

Roundtable（圆桌会议）是一款 AI 驱动的多专家决策辅助系统。用户上传会议录音或输入决策问题后，系统自动构建证据包、调度多个 AI 专家角色进行并发分析与两轮交叉辩论，经 Supervisor 审查校验后生成结构化决策报告。系统支持实时语音交互、人在回路确认、决策记忆追踪，覆盖会议复盘与个人重大决策两大场景，让每一次决策都经得起专家团队级别的审视。

## 三、技术亮点

### 3.1 多 Agent 并发架构

不同于单一大模型的"独角戏"，Roundtable 同时调度 3-7 个具备不同专业背景的 AI Agent（产品经理、架构师、法务、运营、财务等），每个 Agent 基于同一证据包独立输出分析结论。这种设计模拟了真实企业中的跨部门评审会，确保结论不被单一视角绑架。

### 3.2 两轮辩论机制

- **Round 1**：各专家独立分析，产出 claim（主张）
- **Round 2**：专家互相审视对方的 claim，标记同意/质疑/补充，并引用证据支持观点
- **共识计算**：统计每个 claim 的支持率，标记"强共识/多数/孤立/矛盾"四级共识强度

### 3.3 证据绑定与审查校验

每个 claim 必须绑定到原始证据（会议录音转写的具体段落），Supervisor 自动检查：
- 是否有 claim 缺乏证据支撑
- 是否有 claim 超出专家的专业边界
- 是否有 claim 与其他专家结论冲突

对边界问题自动降级或标记为"需用户确认"。

### 3.4 人在回路（Human-in-the-loop）

AI 不替用户做最终决定。对 Supervisor 标记的待确认项，用户可逐一选择"确认/驳回/修改类型"，系统根据裁决结果重新生成最终报告。所有裁决记录持久化，支持事后审计。

### 3.5 记忆与进化

系统自动提取用户决策模式：
- **决策日志**：记录每次决策的问题、结论、关键分歧
- **用户画像**：自动识别用户反复出现的决策盲区（如过度乐观、忽视合规风险）
- **复盘提醒**：用户可设置决策结果追踪，系统定期提醒复盘

### 3.6 零配置部署

- 后端基于 Python FastAPI，单文件 SQLite 数据库，无需额外数据库服务
- 支持 Docker 一键部署
- 多 LLM Provider 自动路由（DeepSeek、Anthropic、OpenAI 等），无配置时自动降级为 mock 模式

### 4.2 核心指标

| 指标 | 数据 |
|------|------|
| 单次完整分析耗时 | 标准模式 15-30 秒，辩论模式 30-60 秒 |
| 支持并发 Agent 数 | 3-7 个（可配置） |
| 语音转写支持格式 | mp3, wav, m4a, ogg, webm |
| 最大单文件音频 | 25 MB |
| 最大证据段数 | 500 段/会话 |
| 支持语言 | 中文、英文（可扩展） |

### 4.3 典型应用场景

**场景一：产品评审会议复盘**
> 产品经理上传 30 分钟 PRD 评审录音，Roundtable 自动识别出 12 个关键 claim，其中 3 个被架构师质疑"技术可行性不足"，2 个被法务标记"需确认合规性"。经用户裁决后，输出带行动项和负责人的最终报告。

**场景二：创业方向决策**
> 创业者输入"要不要从 SaaS 转型做 AI Agent 平台？"，系统调度产品经理、技术负责人、投资人、运营专家进行辩论。最终报告明确指出：技术储备足够（3/4 专家支持），但客户迁移成本高（2 位专家挑战），建议先跑 3 个试点客户验证。

**场景三：投资判断辅助**
> 用户输入房产投资决策，系统识别出用户隐含倾向"过度乐观"， devil's advocate（魔鬼代言人）专家主动挑战租金回报率假设，指出用户未考虑的空置率和政策风险。

### 4.4 与通用 AI 的对比

| 维度 | 通用大模型（如 ChatGPT） | Roundtable |
|------|------------------------|-----------|
| 视角 | 单一模型，单一立场 | 多专家，多立场 |
| 证据 | 不绑定原始材料 | 每个 claim 必须绑定证据段落 |
| 审查 | 无 | Supervisor 自动审查 + 用户确认 |
| 记忆 | 会话级，无长期记忆 | 三层记忆：决策日志 + 用户画像 + 复盘提醒 |
| 可追溯 | 差 | 完整审计链：证据 → claim → 审查 → 用户裁决 → 最终报告 |
